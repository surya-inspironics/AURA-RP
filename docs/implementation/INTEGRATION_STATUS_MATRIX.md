## Integration-control observations

- `BaseAdapter` exposes `MOCK`, `SANDBOX`, and `PRODUCTION` modes and reports safe status fields, but the registry is a process-level singleton; mode/failure state is neither tenant-specific nor durably audited.
- Integrations mode and failure routes have owner/admin guards; financial gold-loan routes do not uniformly bind user-supplied maker/checker/custodian IDs to authenticated membership.
- “Configured” environment variables do not prove a provider client exists. Several adapters still explicitly reject production despite accepting a mode switch.
- `GoldRateAdapter` is an exception to consistent fail-closed behavior: rate retrieval can use free sources or static fallback even when adapter mode is set to production.
- No provider should be represented in UI or customer material as verified, live, or production-ready based solely on adapter name, health label, mode setting, or successful simulator output.

## Provider decisions and credentials required

Before implementation, the product owner/bank must identify: approved market-rate source and entitlement; bank payout/core-banking channel; Razorpay live-mode and webhook arrangement; KYC/CKYC, bureau, and screening providers; device maker/gateway and calibration trust; e-sign/e-stamp provider; notification provider; auction provider; object storage; and the authoritative identity provider. Credentials must be supplied through an approved secret manager, never committed or included in this report.
